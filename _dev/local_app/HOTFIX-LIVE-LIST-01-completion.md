## 사용 방법과 실제 설치

`D:\BDOBarterDev\BDO 물교 실행.lnk`를 더블클릭한다. 대상은 `D:\BDOBarterDev\app\BDO 물교 실행.exe`이며 Python·PowerShell 명령 입력이 필요 없다.

## 물교 목록

자동 확정 값은 표에 바로 표시하고, 확인이 필요한 필드만 별도 입력란으로 표시한다. 해당 필드 수정 후 `최종 물교 리스트로 새 회차 시작` 또는 `현재 회차에 추가`로 기존 회차 모델에 적용한다. 기존 importer의 품목 매칭·중복·충돌 처리를 재사용하며, 보류된 행을 조용히 버리지 않는다. 품목 매칭 실패 시 해당 필드를 다시 수정할 수 있다. 저장 응답을 확인한 후 적용 완료를 표시한다.

기존 고정 수량 규칙을 유지하면서 빠져 있던 육지품→1단계 결과 수량 1을 추가했다. 고정값은 숫자 OCR 호출을 생략한다. 육지품 요구량, 1→2·2→3의 2/3, 특별 교환·주화 결과량, 남은 횟수는 실제로 인식한다. 원문과 읽기 변형 기록은 보존하고 unknown을 임의 숫자로 채우지 않는다.

| 요구 수량 | 78/80 | 80/80 |

기존 숫자 오답 5필드를 실제 crop과 대조했다. 200→20은 아이콘 상단 잡음과 마스킹의 숫자 유실, 10→40·100→10·2→4/unknown은 마스크 판독 오류였다. 숫자 crop의 상단 일부를 제외하고 여백을 둔 영상·반전 영상의 일치 판독과 원색 영상 합의를 사용해 실제 OCR이 필요한 4필드를 바로잡았다. 나머지 육지품 결과량 1은 고정 규칙 누락을 수정했다. 이미지별 정답이나 oracle은 runtime에서 읽지 않는다.

남은 문자열 차이는 `영롱한 비취`의 띄어쓰기, `황금 사막의 모래 반지` 2곳의 기존 catalog 표기, 화면에 잘린 `까마귀 상단 소유의 ...`와 catalog의 전체 이름이다. 따라서 숫자가 모두 맞았다는 결과와 전체 80행 문자열 완전 일치는 구분한다. 새 실시간 캡처와 다른 배율까지 같은 정확도를 보장하는 검증은 아니다.

## 창고

기존 scanner·reference·수량 템플릿과 인식 threshold는 변경하지 않았다. 화면 연결 후 범위를 이동·크기 조절하여 선택 영역을 캡처할 수 있게 기존 ScreenCaptureSession과 ROI 계산을 재사용했다.

`MATCH` 행은 검수 표에서 숨기지만 최종 재고 patch에는 포함한다. 미확정 슬롯만 수정한다. 자동 인식 행의 feedback은 `unchecked`로 보존하여 사람이 검증한 학습 정답으로 만들지 않는다. 실제 browser fixture에서는 자동 확정 50품목과 확인 필요 3칸이었고, 자동값 적용·3칸 수정·단일 저장을 확인했다.

씨앗 주머니 3종은 현재 fixture에서 실제로 `ICON_MATCH_UNKNOWN`이었다. 후보는 정확하지만 1·2순위 점수 차이가 갈퀴 꽃 0.038160, 로아 꽃 0.038891, 앵두나무 0.038357로 기존 기준 0.045보다 작다. 수량은 `QUANTITY_MATCH`다. `MATCH`인데 UI가 재확인을 요구하는 경우는 제거했으며, 이 3종의 실제 보류 원인은 위 점수 차이다. 정답을 강제하거나 전체 threshold를 낮추지 않았다.

## 교섭력·횟수·재고

생성은 현재 회차에 입력한 교섭력을 사용하고, 완료는 현재 회차 비용×실제 완료 횟수를 차감한다. 완료 직전에 최신 회차 교섭력·재고를 동기화한다. 영구 설정의 새 회차 기본 교섭력과 현재 회차 값을 분리한 기존 구조를 유지했다.

확인하고 수정한 기존 계산 문제:

- 교섭력이 교환 비용과 같아도 생성하지 못하던 조건을 `<`로 수정하고 일반/주화의 해당 비용을 비교한다.
- 주화 남은 횟수를 섬별 1/4로 덮어쓰는 동작을 제거하고 실제 목록 횟수를 사용한다. 기존 섬별 우선순위 분류는 유지한다.
- 4→5에서 남은 1~4회를 제외하거나 5회로 자르던 동작을 제거한다.
- 수동 횟수 증가는 실제 남은 횟수와 현재 교섭력을 넘지 못한다.
- 완료 시 교섭력·남은 횟수·소모품 재고가 부족하면 값 변경 전에 중단한다. 부족한 재고를 0으로 잘라 결과품만 얻는 상황을 막는다.

실제 Chrome·임시 DB 검증:

| 입력 / 비용 / 완료 | 교섭력 최종값 | 소모품 | 일반 결과품 |
|---|---:|---:|---:|
| 일반 30,000 / 10,000 / 3회, 수율 3 | 0 | 100→97 | 0→9 |
| 주화 24,000 / 8,000 / 3회 | 0 | 100→97 | 주화는 창고 재고 관리 대상 아님 |
| 일반 10,000 / 10,000 / 1회, 수율 3 | 0 | 100→99 | 0→3 |

교섭력 값을 생성 후 5,000으로 바꾸면 부족한 완료를 막으며, DB/revision/재고가 변하지 않았다. 4→5 남은 2회도 실제 2회로 생성됐다. 응답 유실 재시도, 중복 완료 클릭, 실제 409 재충돌에서 계산은 한 번 수행됐고 재고 delta가 한 번 반영됐다. 새로고침 후 회차·재고가 복원됐다. 기존 일반/주화/7단계 비교 fixture 결과도 유지됐다.

게임의 실제 회당 비용이나 선원·장비 감소율을 새 공식으로 추정하지 않았다. 기존 기본 비용 일반 10,973·주화 15,962와 회차 설정은 유지한다. 위 검증은 입력 교섭력 및 설정된 비용에 대한 생성·차감·저장 정합성 검증이다. 실제 인게임 비용과 일치하는지 확정하려면 같은 효과 상태에서 일반/주화 각 1회의 교환 전·후 교섭력 차이가 필요하다.
