# 추가 요구 구현 및 인식 데이터 검토

## 구현

- 쾌속·균형 브리핑에 총 출항시간을 표시한다. 엔진의 분 값을 초로 환산해 합산하고 마지막에 한 번 반올림한다. 귀환 시간은 기존 totalTime에 이미 포함되어 있어 다시 더하지 않는다. 24시간이 넘어도 시간을 계속 누적한다.
- JSON에서 제외된 행은 원본 행 번호, 사유, 후보와 원문을 보여 준다. 기본값은 제외이며 6개 필드를 수정한 후 삽입을 선택할 수 있다. 기존 품목·중복·충돌 검증을 다시 거치며 선택한 행에 오류가 있으면 적용하지 않는다. 취소 시 회차를 유지한다.
- 미인식 창고 칸은 원본 칸 이미지, 프로그램 후보, 점수와 판정 사유를 보여 준다. 품목 추측 일치/불일치/미확인을 선택하고 실제 품목·수량을 입력한다. 비대상 제외도 유지한다.
- DB schema 3의 warehouse_scan에 원본 PNG, 판독 결과, 기준 자료·아이콘·스캐너·수량 템플릿의 SHA-256을 보존한다. 판독만으로 재고나 회차 revision을 바꾸지 않는다.
- 재고 적용 시 warehouse_feedback에 사용자 확인값과 적용 재고를 같은 SQLite 거래로 저장한다. 어느 한쪽이 실패하면 모두 취소한다. 동일 mutationId 재시도로 기록을 중복 적재하지 않는다.
- 스캔 창의 인식 기록 내보내기(ZIP)는 원본 PNG, 각 칸 PNG, 원래 판독 출력, 사용자 확인 이력, samples.jsonl, manifest.json을 출력한다. 재고와 목표·회차는 다운로드로 바뀌지 않는다.

## 학습 가능성 검토

현재 판독은 템플릿 비교 방식이며 실제 ML 재학습은 구현하지 않았다. 쌓이는 자료는 향후 수동 템플릿 보완과 CPU 기반 품목 분류 실험에 모두 사용할 수 있다. 작은 칸 이미지에서 특징을 추출한 뒤 k-최근접 이웃 등의 분류기를 비교하는 방식을 후보로 판단한다. 이 가능성은 공식 문서와 데이터 규모에 근거한 설계 판단이며 실제 속도·정확도를 측정한 결과가 아니다.

scikit-learn의 최근접 이웃 분류기는 기존 표본과의 거리를 비교해 품목 같은 이산 범주를 예측한다: [공식 문서](https://scikit-learn.org/stable/modules/neighbors.html).

자동 MATCH 및 사용자 미확인 행은 정답으로 간주하지 않는다. 명시적으로 추측 일치/불일치를 확인한 행만 verifiedItemLabel=true다. 입력 수량은 원래 OCR 출력과 별도 보존되며, 품목 확인 여부와 숫자 인식의 정답을 혼동하지 않는다. 비대상 칸은 특정 품목의 정답이 아니라 제외 확인 정보로 남긴다.

동일 이미지의 여러 칸·반복 업로드가 학습 및 평가 양쪽에 섞이면 정확도가 부풀려질 수 있다. 후속 실험에서는 원본 이미지 SHA-256과 촬영 묶음 단위로 학습·평가 자료를 분리하고, 품목별 정답 수·오분류·미인식률·수량 정확도·CPU 지연을 별도로 평가해야 한다. 전처리도 학습 자료로만 맞춘다: [데이터 누출 방지 공식 문서](https://scikit-learn.org/stable/common_pitfalls.html).

이번 버전은 자료를 쌓고 내보내는 단계다. 기록을 저장하는 것만으로 현재 인식 정확도가 자동으로 높아지지는 않는다. 새 기준 자료 적용과 ML 모델의 실제 학습·비교·채택은 이후 검증이 필요하다. 기존 판독 임계값을 낮추거나 모호한 후보를 강제로 확정하지 않았다.
