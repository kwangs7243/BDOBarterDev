## 2. 완료 보류 오류의 재현과 원인

수정 전 동일 데이터에서 다음 두 차단을 재현했다.

1. `팔랑나비 박제품 5개 → 발렌시아 사막 보검 5개` 카드를 완료하면, 5단 최소보존 5개를 침범한다는 이유로 완료가 보류됐다.
2. 이어지는 `발렌시아 사막 보검 5개 → 돌꼬리 당근 건강식 상자 5개`는 6단품이 마스터 창고에 없다는 이유로 완료가 보류됐다.
3. 실제 사용 중 `까마귀의 둥지 청동 촛대 → 까마귀 주화` 카드도 스케줄에 표시됐지만 최소보존 판정 때문에 완료가 보류됐다.

원인은 생성 엔진과 완료 검증의 재고 모델이 달랐기 때문이다.

- 7단 생성 엔진은 5단품을 6단으로 교환하도록 확정한 뒤, 그 6단품을 같은 출항의 7단 교환에 바로 사용한다.
- 그러나 완료 검증은 스케줄 생성 뒤 최소보존과 현재 재고를 다시 검사했다.
- 6단 중간품은 마스터 창고에 저장하지 않는 설계인데도 창고 실재고와 선행 완료 순서를 요구했다.
- 특수·까마귀주화 예외도 조건식에 흩어져 있어, 일부 실제 카드가 예외에서 빠지면 같은 문제가 재발할 수 있었다.

## 3. 적용한 최소 수정

완료 함수 안의 사전 차단 블록을 제거했다. 개별 예외를 더 늘리는 방식이 아니라, **스케줄에 표시된 카드는 완료 버튼을 누르면 항상 반영**하는 원칙으로 단순화했다.

- 최소보존 재검사 제거
- 실제 입력 재고 부족 재검사 제거
- 5→6 선행 완료 요구 제거
- 마스터에 없는 6단 중간품 재고 요구 제거
- 특수 교환·무작위 교환·까마귀주화별 우회 조건 제거
- `완료 보류` 메시지와 그에 따른 조기 종료 제거

입력품이 마스터 재고에 있고 교환 비용보다 적으면 재고는 음수가 되지 않고 0에서 멈춘다. 이후 출력 재고, 교환 목록 수량, 교섭력과 카드 완료 상태는 정상 반영된다. 이미 완료된 카드를 다시 눌렀을 때 중복 차감을 막는 조건만 유지했다.

## 4. 현재 17개가 생성되는 이유

현재 일반 적재 한도는 21,490, 한계 적재 한도는 38,220이다. 지역당 7단 10개를 만들기 위한 6단 적재 무게는 20,000이므로, 현재 적재 설정은 이미 충분하다.

| 동부 | 흰색 애벌레 박제품 | 1 | 5 | 목 잘린 용 조각상(파딕스) | 3 / 5 | 전용 동부 체인 허용 구역 밖, 1회 |

## 5. 3지역 총 30개를 보는 임계치

현재 목록은 지역마다 5→6 행 2개, 대응 6→7 행 2개가 각각 5회씩 있으므로 목록 수량 자체는 30개를 지원한다.

### 반드시 필요한 조건

1. 지역당 적재 한도 20,000 이상
   - 현재 일반 적재 21,490과 한계 적재 38,220은 모두 통과한다.
2. 각 5→6 행에 사용할 5단품 5개
   - 또는 같은 지역의 전용 체인에서 허용되는 4→5 행과 그 4단 입력품 5개가 필요하다.
3. 기본 교섭력
   - 5→6 30회 + 6→7 30회만 계산하면 `60 × 10,973 = 658,380`이다.
   - 현재 확인된 까마귀주화 9곳을 더하면 `658,380 + 9 × 15,810 = 800,670`이다.
   - 4→5 한 묶음(5회)을 더할 때마다 54,865가 추가된다.
   - 가상 혼합 시나리오에서 4→5 다섯 묶음, 7단 30개, 까마귀주화 9곳이 함께 생성됐고 예상 교섭력은 1,074,995로 현재 최대 1,250,000 안이다.

### 현재 재고에서 가장 가까운 조건

- 동부는 `흰색 애벌레 박제품`과 `팔랑나비 박제품`을 각각 5개까지 직접 확보해야 한다.
  - 각각 현재 1개이므로 4개씩 더 필요하다.
  - 대응 4→5 생산지인 파딕스와 오벤은 현재 동부 7단 본대의 연결 허용 구역 밖이다. 이 제한은 경로 알고리즘에 속하므로 수정하지 않았다.
- 서부 `102년 묵은 황금초`는 다음 중 하나가 필요하다.
  - 5단품 자체를 5개 확보, 또는
  - 아지르의 `자수정 파편`을 5개 확보해 4→5 다섯 회를 온전히 실행.
  - 현재 자수정 파편은 1개이므로 4개가 더 필요하다.
- 서부 `정체불명의 암석`, 남부 `젊음을 담은 비약`, `빛바랜 황금용 조각상`은 현재 직접 5단 재고만으로 이미 5회 조건을 만족한다.
- 남부에서도 4→5 보충 동선을 일부러 같이 보고 싶다면:
  - `금주화가 담긴 낡은 상자`는 현재 3개이므로 2개 추가,
  - `해상 기사단의 투구`는 현재 0개이므로 5개 추가가 필요하다.

## 6. 최소보존과 목표재고의 영향

5단 최소보존을 1과 100으로, 여섯 5단품 목표치를 0과 999로 바꾼 대조 실험에서 3지역 5→6→7 수량은 모두 동일했다.

- 동부 2개
- 서부 5개
- 남부 10개
- 합계 17개

따라서 **7단 전용 본대의 수량 임계치를 직접 조종하는 값은 최소보존·목표재고가 아니다.** 실제 직접 조건은 다음이다.

- 지역당 적재 한도
- 5단 실재고
- 연결 가능한 4→5 행의 5회 묶음 존재 여부
- 해당 4단 입력품 5개
- 교섭력
- 전용 지역의 허용 섬 목록

최소보존과 목표재고는 일반 스케줄 및 7단 본대 뒤의 남은 재고 보충 후보 점수에는 영향을 줄 수 있지만, 이번 데이터의 7단 본대 17개를 30개로 직접 늘리지는 않았다.

## 8. 실제 브라우저 검증 상태

`BROWSER_NOT_RUN`

Chrome에 최종 HTML의 로컬 `file://` 탭이 열려 있는 것은 확인했지만, 브라우저 자동화 보안 정책이 해당 탭 연결을 차단했다. 정책상 우회 또는 다른 브라우저 표면을 사용할 수 없어 실제 화면에서의 JSON 붙여넣기, 수동 입력, 완료 클릭, 저장, 새로고침과 백업 복원은 미검증으로 남겼다.

자동 회귀에서는 완료 버튼과 재고·목록·교섭력 갱신, 저장, 새로고침 복원, 백업 복원을 검증했다. 이는 실제 브라우저 검증을 대신했다고 간주하지 않는다.

## 9. 수정하지 않은 문제와 남은 위험

1. 동부 7단의 부족 5단품을 파딕스/오벤 4→5 행으로 같은 본대에서 채우지 못하는 지역 제한
   - 경로·배차 알고리즘 범위이므로 수정하지 않았다.
2. 파딕스의 `흰색 애벌레 박제품` 보충 행은 혼합 가상 재고에서도 같은 출항의 연결 보충으로 쓰이지 않았다.
   - 동부 직접 5단 재고 5개가 있어야 현재 주기 30개가 확실하다.
3. 실제 브라우저 조작 미검증
   - 로컬 파일 접근 정책 차단 때문이다.
4. “5회 미만이면 스케줄 미생성” 기능 미추가
   - 충분 재고에서 이미 5회가 생성되고, 추가 조건은 기존 배차 로직을 건드려야 하므로 이번 범위에서는 불필요하고 위험하다.
5. 완료 시 실제 입력 재고가 비용보다 적으면 재고를 0으로 제한하고 완료한다.
   - 사용자가 명시한 “스케줄에 표시된 카드는 막지 않는다” 원칙의 결과다. 스케줄 생성 뒤 재고를 수동 변경한 경우 부족 경고는 더 이상 나오지 않는다.
