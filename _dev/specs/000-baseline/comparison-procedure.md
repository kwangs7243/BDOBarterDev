# SPEC-000 동일 입력 비교 절차

1. 기준 입력·설정·fixture의 경로와 SHA-256을 먼저 기록한다. 개인 백업의 내용은 복사하지 않는다.
2. reference implementation과 후보 구현에 같은 입력 바이트와 같은 설정을 제공한다.
3. 물교 입력은 정규화된 parsed item명·단계·요구량·수율·횟수를 비교한다. 재고 PATCH는 키와 정수 수량을 정확 비교한다.
4. 스케줄은 출항·경로·교환 항목·횟수·적재 및 교섭력 효과를 의미 필드별 정확 비교한다. 완료는 적용 전후 재고 차이를 비교한다.
5. 허용 오차는 두지 않는다. timestamp와 생성 ID처럼 명시적으로 비결정적인 필드만 비교 전에 제거하고, 제거 필드와 변환 규칙을 결과에 기록한다.
6. 실행 명령, 런타임/브라우저, 입력 해시, 출력 해시, PASS/FAIL을 남긴다. 브라우저 미실행은 `BROWSER_NOT_RUN`이다.
7. 테스트 기대값을 바꾸어 후보 결과를 통과시키지 않는다. 기준 파일 해시가 달라지면 먼저 기준 변경으로 취급하고 원인을 검토한다.

## 허용 변경과 금지 변경

SPEC-000에서는 이 비교 문서와 baseline 산출물만 추가·수정한다. 후속 구현에서 승인된 UI·저장 adapter 변경은 계산 의미를 바꾸지 않는 범위에서 허용될 수 있다. 기준 HTML, scanner, reference 데이터, fixture, 기존 기대값 및 스케줄·경로·완료 의미 변경은 금지한다.
