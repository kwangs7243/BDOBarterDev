# 연금 제작 작업실

## 실행과 저장

일반 실행은 루트의 `BDO 실행.lnk` 또는 `app/BDO 실행.exe`를 사용합니다. 개발 실행은 저장소 루트에서 기존 Python 환경을 사용합니다.

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
& 'D:/BDO/_dev/recognition-local/r006-env-recovery/venv314/Scripts/python.exe' -B -m local_app.launcher
```

새 환경은 README의 설치 절차를 사용합니다. `bdo`와 기존 `bdo-barter` 명령도 같은 공통 실행기를 사용합니다. `http://localhost:18765/`에서 물교 또는 연금을 선택합니다. `/alchemy/inventory`, `/alchemy/history`, `/alchemy/settings`, `/alchemy/recipes/<item_id>` 직접 접근과 새로고침을 지원합니다.

물교 DB는 기존 `%LOCALAPPDATA%/BDOBarter/data/bdo.sqlite3`를 사용합니다. 연금 DB는 `%LOCALAPPDATA%/BDOSuite/alchemy/alchemy.sqlite3`, 스키마 1이며 물교와 테이블·revision·영수증을 공유하지 않습니다. 테스트에서는 두 DB 모두 임시 폴더를 사용합니다. 이번 전수 감사 수정과 중복 중간재 영역 제거는 재빌드한 설치 앱에 적용했습니다. 실제 저장 목표의 읽기 전용 확인과 운영 DB·ROI 보존을 검증했습니다. 이전 배포와 이번 감사·설치의 검증 범위는 [검증 기록](ALCHEMY-VALIDATION.md)에 구분했습니다.

## 재고 확인과 목표

1. 공통 재고에서 품목을 검색하고 실제 수량을 입력합니다. 빈칸은 미확인, `0`은 확인한 0개입니다. 여러 줄을 `품목명 = 수량` 또는 탭 구분으로 붙여넣고 미리보기 후 일괄 적용할 수 있습니다.
2. 대시보드에서 제작품·목표량·기준·우선순위를 선택합니다. 최종 보유량과 현재 보유분에 추가 제작하는 기준을 구분합니다. 추가 제작 기준은 최종품 현재고를 먼저 확인해야 합니다.
3. 목표 상세에서 단계별 트리를 펼칩니다. 보유 중간재를 먼저 사용하고 부족분만 하위 재료로 전개합니다. 공유 재료는 합산 후 배치 횟수를 올림합니다. 예약은 우선순위 숫자가 작은 목표부터 적용하며 실제 차감이 아닙니다.
4. 미확인 중간재는 기본적으로 하위 요구량을 확정하지 않습니다. 사용자가 선택한 `미확인을 0으로 가정하여 계획만 계산`은 보수적 계획 표시이며 실제 재고를 0으로 저장하지 않습니다.

상세의 제작 경로 비교에서 목표별 제작식을 선택합니다. 10개·100개식과 향수 전환 경로는 별도 레시피입니다. 가변 제작식은 완료 작업의 `누적 실제 주 산출량 ÷ 누적 실제 수행 횟수`를 자동 적용합니다. 예를 들어 10회에서 25개, 2회에서 4개를 얻으면 평균은 29/12개이며 작업별 평균을 단순 평균하지 않습니다. 기록이 없으면 제작식의 산출 기준을 가정하고 화면에 표시합니다. 목표별 수동 수율을 저장하면 그 값이 우선하며, 빈칸으로 저장하면 기록 평균으로 돌아갑니다. 고정 산출 제작식은 공식 제작 단위를 유지합니다. 예상 산출은 실제 재고에 더하지 않습니다. 단계 이름 검색, 부족·미확인·제작 가능·최하위 재료 표시, 부족 목록 복사를 제공합니다. 트리는 펼친 가지부터 렌더링합니다.

## 10개·100개 배치 계획과 제작 가능 표시

목표 또는 중간재 상세의 제작 경로 비교에서 `배치 선택 기준`을 저장합니다. 기존 목표는 수동 경로 고정을 유지합니다. 검증된 9개 품목군에서 초과 생산 최소화, 직접 재료 부족량 최소화, 제작 회차 최소화를 선택하면 10개·100개 제작식을 조합합니다. 110개는 100개식 1회와 10개식 1회로 계획하며 각 제작식의 촉매제·비약·정수를 별도로 합산합니다. 부족량 기준은 알려진 직접 투입 재료의 수량 합이고 미확인 투입량을 먼저 줄입니다. 은화 가격이나 전체 하위 제작 비용을 최적화하지 않습니다.

단계별 제작 트리의 각 배치 버튼은 해당 `recipe_id`와 회차로 제작을 시작합니다. 한 배치를 완료하면 실제 재고에 따라 나머지 배치를 다시 계산합니다. 일반·상위 비약은 슬롯 전체를 대체할 수 있으나 같은 슬롯 부분 혼합은 63개 대체 행 모두 근거 미확인으로 금지합니다. 시약의 야생 들풀 계열 1:1 치환과 비약의 3:1 치환은 구분합니다.

`지금 단독 제작 가능`은 해당 단계 하나만 실행할 때의 현재고 기준입니다. `현재고를 계획 순서에 배정 가능`은 앞 단계와 같은 재료를 중복 사용하지 않는 별도 표시입니다. `전체 목표: 계획상 재료 충족`은 하위 필요 재료까지 반영한 결과이며 가변 산출이 있으면 실측 수율에 따른 예상임을 표시합니다. 미확인 재고와 평균 0 수율은 전체 충족으로 표시하지 않습니다.

## 실제 제작

목표 상세의 단계별 제작 계획에서 필요한 품목을 펼치고 `제작 미리보기`를 선택합니다. 10개·100개 혼합 계획은 각 배치 버튼으로 따로 실행합니다. 중복된 `부족한 제작품·중간재` 영역은 제거했습니다. 기록이 없는 가변 제작은 횟수를 직접 입력합니다. 제작 경로·횟수·소비할 대체 재료를 확인하고 `재료 차감하고 제작 시작`을 누릅니다. 서버는 최신 revision과 실제 재고·타 목표 예약을 재확인하고 재료 차감·진행 작업·원장·영수증을 한 트랜잭션으로 저장합니다. 미확인·부족 재료와 미검증·순환 제작식은 차단합니다. 임의의 일반/상위 재료 혼합은 하지 않습니다.

진행 중인 제작에서 `결과 입력`을 누르고 실제 수행한 횟수와 일반품·상위품·부산물 수량을 각각 입력합니다. 미수행 회차의 재료는 반환합니다. 실제 산출만 재고에 추가하며, 미확인 결과물은 사용자가 제작 전 보유량을 확인해야 추가할 수 있습니다. 계획상의 산출물은 완료 전 재고로 사용할 수 없습니다.

실제로 전혀 제작하지 않은 경우에만 `미실행 취소`로 전체 재료를 반환합니다. 기록에서 완료 결과를 정정할 수 있으며, 이후 소비와 충돌하여 음수가 되면 자동 정정을 중단하고 원장을 유지합니다. 게임의 실제 수량을 확인한 뒤 수급·사용의 절대 수량 보정 거래와 사유로 조정합니다.

완료한 작업의 실제 수행 횟수와 일반품 산출량을 기존 DB에 계속 보관하고 다음 계획에서 누적 수율로 사용합니다. 취소·미수행 회차·진행 중 작업은 수율에 넣지 않습니다. 산출량 정정은 같은 작업의 최신 결과로 다시 계산하여 중복 집계하지 않습니다. 재시작·백업 복원 뒤에도 기록에서 같은 수율을 재구성합니다. 제작 경로·투입 재료/대체재·제작식 수량이 달라진 기록은 섞지 않습니다. 기록상 평균 산출이 0이면 횟수 계산을 보류합니다.

모든 변경은 고유 트랜잭션 ID와 시간·유형을 기록합니다. 중복 요청은 같은 영수증을 반환하고 다시 차감·추가하지 않습니다. 저장 응답이 유실되면 `저장 결과 재확인`으로 같은 ID를 재시도합니다. 저장 중이나 미저장 입력 중 이동은 보호합니다.

## 백업과 레시피 관리

`데이터·백업`에서 전체 데이터를 JSON으로 내려받습니다. 재고·목표·작업·원장·기록·영수증·카탈로그·UI 설정을 포함합니다. 복원은 파일 검증과 수량·원장 일치 검증을 거친 미리보기 후 실행합니다. 교체 전 현재 연금 데이터는 같은 DB의 `restore_backups`에 보관하며 완료 메시지에서 내려받을 수 있습니다. 디스크 자체 손상에 대비하려면 내려받은 JSON을 별도 드라이브에 보관합니다.

제작식 편집은 산출 단위·유형·재료 수량·방식·요구 단계·출처·검증 상태를 수정합니다. 기본 배포 JSON은 덮어쓰지 않고 연금 DB에 사용자 카탈로그로 저장합니다. 입력 수량을 변경한 재료의 기존 대체 비율은 해제하여 잘못된 치환을 막습니다. 카탈로그 JSON 가져오기·내보내기도 지원합니다. 같은 화면에서 트리 기본 표시와 재고 기본 검색어를 저장하며 백업·복원에 포함합니다. 검증 필요 제작식은 재고 차감에 사용하지 않습니다.

카탈로그는 저장 당시 기준 배포본과 사용자 수정본, 최신 배포본을 비교합니다. 사용자 수정이 없는 항목은 최신 값으로 표시하며 조회만으로 DB를 변경하지 않습니다. 양쪽에서 바뀐 항목은 `배포 카탈로그 갱신`에서 내 수정 또는 배포 수정을 선택합니다. 충돌한 제작식은 해결 전 새 제작에 사용할 수 없습니다. 선택 병합·카탈로그 저장 전 전체 연금 상태를 자동 백업하고, 진행·완료 작업의 과거 레시피 스냅샷은 유지합니다. 기준 버전을 모르는 기존 수정본은 그대로 유지하며 자동 병합을 보류합니다. 백업에는 기준본과 수정본을 함께 보관하고 구형 스키마 1 백업도 읽습니다.

## 데이터 범위와 검증 의미

초기 제품은 조화 계열 10종, 대양 3종, 생활 2종, 향수 6종에 검증된 조화 불멸형 5종을 더한 26종입니다. 등록된 제작식과 하위 시약·혈액·오일·비약을 외부 수급 재료까지 전개합니다. 확률 부산물, 기본 채집물·상점 구매 재료 등은 외부 수급 경계를 표시합니다. 하나의 품목 ID를 모든 목표에서 공유합니다.

`verified`는 등록한 입력·배치·최소 산출을 기재된 자료와 대조했다는 뜻입니다. `source_kind=official`의 공식 패치 대조와 보조 DB 대조는 화면에서 구분합니다. 보조 DB 대조를 공식 제작 노트 전체 실사 완료로 해석하지 않습니다. 확인하지 못한 요구 숙련 단계는 `null`/미확인으로 남겼습니다. 새 게임 화면에서의 재료·수율 실사는 별도입니다. 재료·중간재·상위품·완제품 170종의 실제 게임 아이콘을 로컬 파일로 포함합니다. 2026-10-24 전체 170종을 BDO Codex의 게임 품목 ID와 교차 검증하여 현재 아이콘으로 교체했습니다. 같은 이름의 퀘스트 품목을 제외했고 대왕 고래 오일은 같은 게임 ID의 현행 명칭인 대양의 오일과 대조했습니다. 기존 저장 카탈로그의 PNG 주소도 현재 WebP 아이콘으로 제공합니다. 원래 출처 기록은 함께 보존했으며 개별 출처 URL·원본 SHA-256·크기는 `alchemy/data/icon-sources.json`에 기록했습니다. 게임 이미지의 권리는 펄어비스에 있으며, 이 파일은 별도의 배포 라이선스를 부여하지 않습니다. 실행 중 외부 이미지 요청은 하지 않습니다.

이번 감사 자료는 `alchemy/data/recipe-audit.json`의 87개 레시피별 필드·근거·변경 전후와 `alchemy/data/icon-audit.json`의 170개 이미지 대조 기록입니다. 감사 상태와 기존 `verification`은 별개입니다. 87개 모두 개별 근거를 연결했고 78개 확인, 9개는 산출 유형·대체 경로 일부가 미해결입니다. 입력·출력 수량을 추정으로 변경하지 않았습니다. 현행 공식 직접 근거 33개, 보조 직접 근거 54개로 구분합니다. 개별 출처가 이전 공식 페이지보다 명확한 5개는 보조 근거로 재분류했습니다.

대양의 오일은 이전 이름 대왕 고래 오일과 같은 저장 ID를 사용합니다. 자연의 흔적·열매 통합과 심해의 비약 등 과거 명칭을 별칭으로 보관하여 검색·일괄 재고 입력에서 인식합니다. 아이콘 실패 시 `이미지 확인 필요` 플레이스홀더를 표시합니다. 동일 원본인 782/783은 허용 예외이며 이번 실제 게임 신규 캡처 대조는 수행하지 않았습니다.

```powershell
& $env:PYTHON -B -m pytest local_app/tests/backend/test_alchemy_engine.py local_app/tests/backend/test_alchemy_storage.py local_app/tests/backend/test_alchemy_icons.py local_app/tests/backend/test_alchemy_yields.py local_app/tests/backend/test_alchemy_audit.py -q
node local_app/tests/browser_alchemy.mjs
node local_app/tests/browser_alchemy_yields.mjs
node local_app/tests/browser_alchemy_audit.mjs
```

브라우저 검사는 임시 DB·별도 프로필·별도 localhost 포트에서 수행합니다. 실제 카탈로그를 사용하지만 실제 게임 제작 성공이나 설치 앱 배포 검증을 대체하지 않습니다. 전체 명령은 [TESTING.md](TESTING.md)에 있습니다.
