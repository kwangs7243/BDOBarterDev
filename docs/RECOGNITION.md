# 현재 인식과 개선 방향

## 물교

`local_app/tools/trade_live_ocr.py`가 행·필드를 나누고, `trade_template_reader.py`가 글자 전체의 전경을 추출·정규화한 특징 해시를 조회합니다. 현재 bank는 `local_app/recognition_data/trade-templates.json`이며 reference 881개입니다. 전체 모양·라벨이 충돌 없이 일치하는 입력만 처리하고 나머지는 기존 OCR 경로로 넘깁니다.

정답 조회는 모든 이미지를 순서대로 비교하는 방식이 아닙니다. native/scaled 특징 키로 조회합니다. 현재 적용 조건은 원본 native pixels, 987×456 입력과 고정 영역 조건입니다. 위치 보정과 전체 숫자·잘린 경계 검사를 유지합니다.

| 종류 | 현재 서로 다른 정답 값 |
|---|---:|
| 섬 | 87 |
| 품목 | 162 |
| 남은 횟수 | 7 |
| 수량 | 34 |

이 개수는 모든 마스터/가능한 수량을 지원한다는 뜻이 아닙니다. bank 버전과 SHA-256은 reader의 고정값으로 검사합니다. 파일이 없거나 무결성·입력 조건을 만족하지 않으면 정답 조회를 사용하지 않고 OCR로 처리합니다.

미일치 입력은 Korean PP-OCRv5 mobile ONNX CPU 모델을 사용합니다. 동일 이미지의 OCR 재사용은 현재 worker 배치 안에서만 유지하며 이전 회차의 값으로 현재 회차를 채우지 않습니다. 게임 교환 규칙으로 정해지는 값, 이미지 대조 결과, OCR 후보, 사용자 수정은 출처를 구별합니다.

## 창고

창고 품목은 `reference/`의 70종 카탈로그·아이콘과 대조합니다. 숫자와 전체 슬롯 보정은 `local_app/recognition_data/warehouse-templates.npz`의 검증 자료를 사용합니다. 설치 패키지에서는 같은 파일을 `tools/warehouse_patch/quantity_templates.npz`로 포함합니다.

`tools/warehouse_patch/quantity_templates.npz`의 원본과 배포 보정 파일을 혼동하지 않습니다. 빌드는 검증 행·출처가 없는 원본 자료를 현재 보정 자료로 대신하지 않습니다. 모호한 수량은 검수 대상으로 유지하며 5와 3처럼 비슷한 숫자를 확신만으로 자동 확정하지 않습니다.

## 표본 확장 원칙

사용 이력의 이미지·인식 후보와 정답 자격은 구별합니다. 잘렸거나 불확실한 표본, 규칙으로 채운 값, 충돌하는 라벨을 무조건 정답으로 등록하지 않습니다. 확인 가능한 crop을 대조하고 회차·원본 이미지가 학습/등록과 평가에 섞이지 않게 나눕니다.

1. 저장 자료와 출처·중복·검수 상태를 확인합니다.
2. 새 정답 후보를 이미지와 대조하고 충돌·누락을 보류합니다.
3. 평가 회차에서 잘못 자동 통과한 값, 검수 변화, fallback 동일성과 OCR 호출 수를 확인합니다.
4. 낮고 비슷한 PC 부하에서 시간을 비교한 뒤 bank와 reader의 해시를 함께 갱신합니다.
5. 패키지 입력과 설치 데이터 보존을 별도로 검증합니다.

현재 제품에는 ML 분류나 숫자 한 자리 정답 조합을 적용하지 않았습니다. 2026-10-19 숫자 실험에서는 두 방식의 엔진 개선이 약 5%였고 정확성·검수 감소는 확인하지 못했습니다. 현재는 기존 구조와 검증 표본 확장을 유지하기로 결정했습니다. [실험과 결정](decisions/2026-10-19-numeric-recognition.md)

과거 `trade-template-v1` 실험 코드·manifest는 [archive 안내](archive/README.md)에 있습니다. frozen baseline의 `_dev`는 과거 사본 내부 경로이므로 현재 소스 위치에 맞춰 고치지 않습니다.
